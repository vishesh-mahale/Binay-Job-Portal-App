## 4. Findings


### P9-C1 — `UserContextClient` / `SystemClient` share one trusted pool; RLS read-path boundary is nominal (HIGH)

- **File/line:** `src/clients.ts` L7–17; `src/database.ts` L9–13, L5–6
- **Evidence:** Both classes inject the same `DatabaseService` and call `this.db.query(...)` over one `Pool` created from a single `DATABASE_URL` (trusted/system credential). `UserContextClient` exposes the same query capability as `SystemClient` minus `transaction`. The DI symbols `USER_CONTEXT_CLIENT`/`SYSTEM_CLIENT` exported at `database.ts` L5–6 are referenced nowhere — intended token wiring was never completed.
- **Impact:** Decision-01's mandatory client-boundary rule (`UserContextClient` → approved personal/catalog reads with RLS via user-JWT context propagation; `SystemClient` → server-only trusted writes) is only structurally suggested, not behaviourally enforced. When Phase 09-B..G modules arrive, any developer using `UserContextClient.query` will silently perform RLS-bypassing trusted reads with no JWT context sent to PostgreSQL. The report wording "Separate UserContextClient and SystemClient classes" is literally true but materially overstates the security property.
- **Recommended fix:** Either (a) give each client its own adapter — e.g., per-request JWT claims propagated to the session inside an explicit transaction pool, or a distinct restricted connection role, with writes blocked — or (b) keep current wiring but add code-level enforcement + tests (type-level restriction of mutation APIs, runtime guard/logging on non-read SQL from `UserContextClient`, distinct DI tokens so cross-injection becomes test-detectable). Record the chosen path in a short slice-README note until a full ADR exists.
- **Blocks:** business-module start; gate §6 separation tests must prove more than class identity (see P9-C4).

### P9-C2 — pg Pool has no `error` listener; idle-client errors can crash the process (MEDIUM)

- **File/line:** `src/database.ts` L11 (`new Pool({...})`; only `query/transaction/onModuleDestroy` defined)
- **Evidence:** `pg` emits `'error'` on pooled clients for asynchronous failures (backend restart, terminated connection). Node treats unhandled `'error'` events as fatal. No handler attached anywhere in the slice.
- **Impact:** Under a real outage (connections dropped while idle) the API process can crash instead of failing requests gracefully; the readiness test only covers a rejected query.
- **Recommended fix:** In constructor: `this.pool.on('error', (err) => …safe log with err.code only…)` plus a unit test emitting `pool.emit('error', …)` asserting no throw.
- **Blocks:** production-readiness claim for this slice.

### P9-C3 — Startup failure path bypasses documented fail-fast logging (MINOR)

- **File/line:** `src/app.module.ts` L8 (`const config = loadConfig();` at module scope); `src/main.ts` L10–11
- **Evidence:** Invalid env throws during `require('./app.module')` at import time — before `bootstrap()` runs — so `bootstrap().catch(...)` (`main.ts` L11, prints only `API_STARTUP_FAILED`) never handles it; Node prints an uncaught stack trace, and zod issues can include received values (enum mismatch etc.) which would surface in that trace. Config is also parsed twice (module import + main).
- **Impact:** Fail-fast still occurs (nonzero exit) but via an unintended path that can echo environment values and contradicts the intended startup-failure handling.
- **Recommended fix:** Parse once in `main.ts` before importing `AppModule`; inject via DI/dynamic module; map zod errors to a redacted constant message (`CONFIG_INVALID`); keep catch-all constant-string fallback.
- **Blocks:** NO.

### P9-C4 — Security-negative test coverage thinner than gate requirements (MEDIUM)

- **Files:** `src/auth.spec.ts` (2 cases), `src/clients.spec.ts` L1–2 (single identity assertion), `src/database.spec.ts` (rollback only)
- **Evidence / missing:** tampered signature, `alg:none`/RS256 confusion tokens, missing `sub`, missing `Authorization` header, no-exp policy; COMMIT happy-path; UserContextClient mutation-restriction; no test for "no external call inside transaction"; liveness endpoint untested.
- **Impact:** Gate §6 explicitly requires JWT/request-context + trusted-client separation tests and a no-external-call-in-transaction test; attack-class regressions and boundary misuse would currently pass CI silently.
- **Recommended fix:** Add focused specs per list above plus an architectural guard test asserting controller-layer cannot reach raw pool SQL unguarded.
- **Blocks:** NO individually; part of CONDITIONAL upgrade.

### P9-O1 — Clean standalone install unverified; no lockfile committed (OPEN)

- **File/line:** `package.json` (^-ranged deps); lockfile absent from slice root
- **Evidence:** File listing shows no `package-lock.json`; implementing agent's report states deps resolved from shared local cache and standalone install must not be relied on in CI.
- **Impact:** Non-reproducible builds/supply-chain drift; existing `node_modules` is not valid CI evidence.
- **Recommended fix:** Pristine install → commit lockfile → record `npm ci && npm run build && npm test` as CI evidence; add `.gitignore` for `node_modules/`, `dist/`, `.env`.
- **Blocks:** NO locally; REQUIRED before CI/deployment gates.

### P9-N1 — Redaction misses quoted-JSON patterns; correlation ID not carried into logs/envelope (MINOR)

- **Files:** `src/observability.ts` L3–4 (regex requires `[=:]` after the keyword, so `"password":"x"` inside serialized JSON strings is unmatched); L8 (`log()` omits request id); `src/errors.ts` L10 (envelope lacks `request_id`); `src/request-context.ts` stores id on `req` but nothing consumes it.
- **Impact:** Residual secret-leak surface in JSON-style payloads; weaker request↔log↔error traceability than Phase-07 §10 requires.
- **Recommended fix:** Add quoted-form pattern to redactor; thread `requestId` into SafeLogger (AsyncLocalStorage or explicit field); include `request_id` in error envelope body.
- **Blocks:** NO.

### P9-N2 — Hardening backlog (MINOR/INFO)

- `auth.ts` accepts tokens without `exp` and skips `iss`/`aud`/`nbf` — acceptable for current Supabase-shaped tokens; encode policy + issuer pin later.
- `config.ts` L6 — `DATABASE_URL`: `.url()` branch admits `http://…`; any string merely starting with `postgres` passes. Tighten to explicit scheme check.
- `errors.ts` L9 — unlisted 4xx statuses collapse to `VALIDATION_ERROR` (a future 429 would mislabel); extend map as vocabulary codes appear.
- No CORS/helmet/rate-limit hooks yet — fine pre-endpoint; revisit with first adapters.
- `dist/` build output sits in tree — ignore once gitignore hygiene lands (see P9-O1).
