## 3. Detailed Findings

### Item 1: Authorization Gap in `updateDraft` and `publish` — **FIX REQUIRED**

**Evidence:**

- `getCompanyJob` (`jobs.ts:63-74`) correctly includes:
  ```sql
  OR EXISTS (
    SELECT 1 FROM public.company_members cm
    WHERE cm.company_id = j.company_id AND cm.user_id = $3
      AND cm.is_active = TRUE AND cm.left_at IS NULL
  )
  ```

- `updateDraft` (`jobs.ts:94`) and `publish` (`jobs.ts:115`) use:
  ```sql
  AND (j.created_by = $3 OR EXISTS (
    SELECT 1 FROM public.companies c WHERE c.id = j.company_id AND c.owner_id = $3 AND c.deleted_at IS NULL
  ))
  ```

**Impact:** An active HR or employer company member (`company_members.is_active = TRUE, left_at IS NULL`) who did not personally create the job draft receives `404 NOT_FOUND` instead of `403 FORBIDDEN` or success. This contradicts Decision-07 J2: "HR/employer may manage jobs only within their active company membership."

**Fix:** Add `company_members` active check to `updateDraft` and `publish` WHERE clauses:

```sql
AND (
  j.created_by = $3
  OR EXISTS (SELECT 1 FROM public.companies c WHERE c.id = j.company_id AND c.owner_id = $3 AND c.deleted_at IS NULL)
  OR EXISTS (SELECT 1 FROM public.company_members cm WHERE cm.company_id = j.company_id AND cm.user_id = $3 AND cm.is_active = TRUE AND cm.left_at IS NULL)
)
```

### Item 2: Reference Code Not Generated — **NEEDS_HUMAN_DECISION**

**Evidence:** `createDraft` (`jobs.ts:41-44`) does not generate `reference_code`. SQL default is `NULL` (`05_jobs.sql:112`). The `05_jobs.sql:112-114` comment says "Generated by NestJS at job creation time. Example format: JOB-2026-000123."

**Impact:** `reference_code` will be `NULL` for all created drafts. The `unique_job_reference_per_company` constraint (`05_jobs.sql:201`) allows multiple NULLs, so no DB error occurs, but the business intent per SQL comments is not met.

**Decision needed:** Should `createDraft` generate `reference_code` (e.g., `JOB-{year}-{sequence}`) or is this deferred to publish time?

### Item 3: Missing Routes — **NEEDS_HUMAN_DECISION**

**Evidence:** Decision-07 J1 defines 11 routes. Only 4 are implemented:
- `POST /api/v1/companies/:companyId/jobs` ✅
- `GET /api/v1/companies/:companyId/jobs/:jobId` ✅
- `PATCH /api/v1/companies/:companyId/jobs/:jobId` ✅
- `POST /api/v1/companies/:companyId/jobs/:jobId/publish` ✅

Missing: `pause`, `resume`, `close`, `archive`, `submit-for-approval`, `approve`, `reject`.

**Impact:** This is expected — Decision-07 implementation gate order places lifecycle commands after document sync. The 4 implemented routes cover draft CRUD and the primary publish command, which is the minimal viable scope.

### Item 4: `publish()` Missing `expires_at` Setting — **NEEDS_HUMAN_DECISION**

**Evidence:** `publish()` (`jobs.ts:107-111`) sets `status`, `published_at`, `published_by`, and `updated_at`. It does not set `expires_at`. The SQL column exists (`05_jobs.sql:165`). Decision-07 J4 defines expiry via `pg_cron` + `expire_due_jobs()`, which checks `expires_at IS NULL OR expires_at > NOW()`.

**Impact:** Jobs published without `expires_at` will never expire. This may be intentional (employer controls expiry separately) or may need a default (e.g., 30 days from publish).

### Item 5: No CORS Configuration — **MEDIUM**

**Evidence:** `main.ts` has no `app.enableCors()`. Browser cross-origin requests are blocked.

**Impact:** Not specific to jobs — global issue. Documented in previous auth reviews.

### Item 6: No Rate Limiting — **LOW**

**Evidence:** No `@Throttle()` or rate limiting middleware on job endpoints.

**Impact:** Low risk for internal company operations; higher risk if public search endpoints are added without rate limiting.
