📁 File Reference: [`app/core/database.py`](file:///c:/Users/ADMIN/OneDrive/Desktop/Vishesh/Binay-Job-Portal-App/07-fastapi-ai-worker/app/core/database.py)

Hamari Database Engine Configuration mein **5 Critical Parameters** hain jo Production High-Traffic / Serverless environment ke liye tuned hain:

```python
self.engine = create_async_engine(
    self.settings.DATABASE_URL,
    echo=False,
    pool_size=self.settings.DATABASE_MAX_POOL_SIZE,  # Default: 20
    max_overflow=10,                                   # Extra 10 connections under surge
    pool_pre_ping=True,                               # 👈 Ping before every query!
    pool_recycle=3600,                                # Recycle connections after 1 hr
    connect_args={
        "statement_cache_size": 0,                    # 👈 Transaction Pooler compatibility (Port 6543)
        "prepared_statement_cache_size": 0,
        "ssl": "require"                             # Auto-enabled on non-localhost
    }
)
```

---

### 🔬 Deep Dive: Is Pool Config Ka Architectural Purpose Kya Hai?

#### 1. `pool_pre_ping=True` (Stale Connection Shield):
* **Problem:** Cloud Run instances jab idle baithte hain, to firewalls ya Supabase PgBouncer silently network connection terminate kar deta hai.
* **Solution:** Har naye query execution se pehle SQLAlchemy socket par ek light ping bhejta hai. Agar connection mar chuka hai, to background mein naya connection open karta hai bina Application level Exception throw kiye!

#### 2. `max_overflow=10`:
* **Problem:** Normal state mein app 20 connections maintain karti hai (`pool_size=20`). Lekin agar suddenly Cloud Tasks 50 parallel requests bhej de, to kya hoga?
* **Solution:** Engine temporary **10 extra overflow connections** spin-up karta hai. Surge khatam hote hi in overflow connections ko close kar deta hai.

#### 3. `statement_cache_size=0`:
* **Problem:** Supabase Transaction Pooler (Port 6543) par query send karte waqt `asyncpg` default server-side prepared statements error throw karta hai.
* **Solution:** Statement caching disable karke Port 6543 ke sath 100% stable communication enable hoti hai.

### 🔄 Safe Session Context Managers: `get_session()` vs `transaction()`

Application code direct DB queries nahi chalta, wo `DatabaseManager` ke 2 Context Managers use karta hai:

```python
# 1. READ-ONLY QUERY (Auto-Close)
async with db_manager.get_session() as session:
    result = await session.execute(select(CandidateProfile).where(...))

# 2. ATOMIC TRANSACTION WRITE (Auto-Commit & Auto-Rollback)
async with db_manager.transaction() as session:
    await session.execute(update_statement)
    await session.execute(outbox_insert_statement)
    # If any error occurs inside block -> AUTO ROLLBACK!
    # If block exits cleanly -> AUTO COMMIT!
```

## 🔒 Module 3.4: Zero-Trust Security Lifecycle (`app/core/security.py`)

📁 File Reference: [`app/core/security.py`](file:///c:/Users/ADMIN/OneDrive/Desktop/Vishesh/Binay-Job-Portal-App/07-fastapi-ai-worker/app/core/security.py)

```text
Cloud Tasks Request ➔ HTTP Header: Authorization: Bearer <Google-Signed-OIDC-JWT>
                                            │
                                            ▼
                           OIDCTokenValidator (security.py)
                                            │
               ┌────────────────────────────┼────────────────────────────┐
               ▼                            ▼                            ▼
      1. Fetch & Cache JWKS         2. Verify RS256           3. Service Account
         Google Public Certs           JWT Expiry & Issuer       Allowlist Match Check
```

### 🔑 Security Verification Steps:

1. **Google Public Certs Caching (JWKS):**
   - Google ke public keys `https://www.googleapis.com/oauth2/v1/certs` se fetch hoti hain aur memory mein cache hoti hain.
   - Har request par Google ko hit nahi kiya jata (Performance Boost).
2. **RS256 Signature Check:**
   - Verify hota hai ki token asli Google Auth Server ne hi sign kiya hai.
3. **Issuer & Expiry Check:**
   - `iss == "https://accounts.google.com"` aur token expire to nahi hua.
4. **Service Account Allowlist Verification (`GOOGLE_OIDC_ALLOWED_SERVICE_ACCOUNTS`):**
   - Sirf hamare specific Google Cloud Tasks Service Account email (`test@binay-job-portal-dev.iam.gserviceaccount.com`) ke tokens allow hote hain. Baaki sab **HTTP 401 Unauthorized** se reject hote hain!
