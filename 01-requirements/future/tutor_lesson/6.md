Jab `07-fastapi-ai-worker` kisi task ko successfully process kar leta hai (e.g. Resume Parse ho gaya ya Candidate Search Vector update ho gaya), to baki microservices (Jaise Notification Service, Matching Engine, Analytics) ko kaise pata chalta hai?

---

### ⚛️ Dual-State Atomic Write Problem:

```text
❌ WRONG APPROACH (Bina Outbox Ke):
1. DB Commit (Data Saved in candidate_search_profiles) ✅
2. Network Crash / Message Queue Down! 💥
3. Downstream Event Not Sent ❌ ➔ System Desynced!
```

```text
🟢 RIGHT APPROACH (Transactional Outbox Pattern):
async with db_manager.transaction() as session:
    await save_candidate_search_profile(session, profile_data) # Write 1: Data State
    await save_processed_event(session, event_id)               # Write 2: Idempotency
    await emit_outbox_event(session, "candidate.projection.rebuilt", payload) # Write 3: Outbox
    # ALL 3 WRITES COMMIT AT THE EXACT SAME MILLISECOND IN 1 TRANSACTION!
```

#### Outbox Events Emitted by Worker:
* `candidate.resume.parsed` ➔ Triggers NestJS to send email notification to Candidate.
* `candidate.projection.rebuilt` ➔ Triggers Match Engine to recalculate Job Matches.
* `job.enriched` ➔ Triggers Recruiter Notification.

## 🔗 Module 6.3: End-to-End Request Tracing (`x-trace-id`)

📁 File Reference: [`app/core/logging.py`](file:///c:/Users/ADMIN/OneDrive/Desktop/Vishesh/Binay-Job-Portal-App/07-fastapi-ai-worker/app/core/logging.py)

Distributed Microservices Architecture mein ek user action multiple services se guzarta hai:

```text
User Browser ➔ NestJS API (trace_id: "trc_999") 
                   ➔ Cloud Tasks (trace_id: "trc_999") 
                       ➔ FastAPI Worker (trace_id: "trc_999") 
                           ➔ Supabase DB (trace_id: "trc_999")
```

### How `x-trace-id` Works:
1. NestJS request handle karte hi HTTP Header mein `x-trace-id: trc_999` generate karta hai.
2. Cloud Tasks is header ko propagate karke FastAPI Worker tak lata hai.
3. FastAPI ka [`request_lifecycle_middleware`](file:///c:/Users/ADMIN/OneDrive/Desktop/Vishesh/Binay-Job-Portal-App/07-fastapi-ai-worker/app/main.py#L123) is trace_id को extract karke Python `structlog` ContextVar mein bind kar deta hai.
4. Worker ka **har single log line** automatically `"trace_id": "trc_999"` print karta hai.

* **Debugging Power:** Google Cloud Logging mein sirf `trace_id = "trc_999"` search karo ➔ Us specific user action ke saare logs (NestJS + Cloud Tasks + FastAPI + DB) ek line mein aane lagte hain!

## ⚡ Module 6.4: Circuit Breaker Pattern (`app/core/circuit_breaker.py`)

📁 File Reference: [`app/core/circuit_breaker.py`](file:///c:/Users/ADMIN/OneDrive/Desktop/Vishesh/Binay-Job-Portal-App/07-fastapi-ai-worker/app/core/circuit_breaker.py)

Socho OpenAI ya Vertex AI API 15 minute ke liye completely Down / Outage ho gayi!

Agar worker bar-bar timeout aane par bhi API ko hit karta rahega:
* Worker ke saare active database connections wait karte-karte hang ho jayenge (Thread Starvation).
* Cloud Tasks queue overload ho jayegi.

---

### 🔌 Circuit Breaker States:

```text
        ┌────────────────────────────────────────────────────────┐
        │                                                        │
        ▼                                                        │
┌──────────────┐     5 Failures Consecutively     ┌──────────────┐
│ CLOSED       │ ───────────────────────────────► │ OPEN         │
│ (Normal Ops) │                                  │ (Fast Fail!) │
└──────────────┘                                  └──────┬───────┘
        ▲                                                │
        │                                                │ 60 Seconds Timeout Expired
        │                                                ▼
        │        Test Call Succeeds               ┌──────────────┐
        └──────────────────────────────────────── │ HALF-OPEN    │
                                                  │ (Testing)    │
                                                  └──────────────┘
```

1. **CLOSED (Normal):** Traffic normal chal raha hai.
2. **OPEN (Tripped):** Agar 5 consecutive API calls fail/timeout ho gayi ➔ Circuit OPEN ho jata hai. Agli 60 seconds tak worker AI API ko call hi nahi karta! Seedha instant HTTP 503 Return karta hai (Fast Failure). Isse Cloud Run aur DB hang hone se bach jate hain.
3. **HALF-OPEN (Recovery):** 60 seconds baad circuit 1 test request bhejta hai. Agar wo test call succeed ho gayi ➔ Circuit wapas CLOSED (Normal) ho jata hai!
